# v1.1.4 正式发布总结

日期：2026-10-05（本地时间）

## 发布结论

本版以用户实际验证的 ICU 修正版为基础，按用户要求转为正式版。
用户反馈游戏卡顿略有改善；目前没有证据证明掉帧已经彻底解决。
本次正式化不再调整识别算法或游戏输入行为。

- 版本：v1.1.4，ONNX Auto。
- 程序：星布谷地钓鱼助手_ONNX_auto.exe。
- 发行包：starvalley-fishing-assistant-v1.1.4-onnx-auto.zip。
- GitHub：https://github.com/citiao1/starvalley-fishing-assistant/releases/tag/v1.1.4

## 已完成优化

1. 咬杆检测、自动喂食、预览都关闭时，跳过启动时的采集和模型初始化；运行中关闭后暂停采集。
2. 关闭相关功能后，跳过不必要的图像缩放、喂食 ROI 复制和推理提交。
3. 默认采集和推理目标从 15 FPS 降至 10 FPS，保持 768 输入和默认关闭实时预览。
4. ONNX Runtime 使用单线程、顺序执行；推理线程尝试设置低于普通优先级。
5. Auto 模式要求 DirectML 至少具备 20% 的测试耗时优势，否则优先 CPU。
6. 保留全画面咬杆识别、zero -> not_found -> nonzero 喂食语义、前台输入保护和 F12 紧急停止。

## 性能证据与局限

历史 PresentMon 短时采样：基线约 67.5 FPS，DXcam 仅采集约 66.3 FPS，
mss 仅采集约 58.2 FPS，CPU 10 FPS 推理约 63.9 FPS，DirectML 约 59.0 FPS。
这些测试存在前台切换和场景差异，不能作为严格的因果证明或本版提升比例。
全部选项关闭后的旧采样也出现帧率下降，问题不能简单归因于 YOLO。
用户已经测试采集和推理同时使用 4060，仍不能消除卡顿。

目前继续保留 DXcam，没有凭上述数据切换为 mss，也没有引入可能造成帧读写竞态的零拷贝改动。
Auto 的随机图像基准衡量助手推理耗时，不衡量游戏帧时间；低 CPU/GPU 总占用不等于没有调度、同步或呈现延迟。
后续应做同场景、持续前台、重复多轮的开关助手 A/B，比较游戏帧时间 p50/p95/p99。

## 启动错误根因与修复

一次为避开旧目录文件占用而直接调用 PyInstaller 的构建，绕过了脚本中的 PATH 过滤。
依赖分析因此从 Codex 运行环境的 Poppler 目录收集了 ICU 78：
其 icuuc.dll 导出 ucnv_open_78，而 Qt6Core.dll 导入 ucnv_open。
这是发行包依赖冲突，不是用户游戏或显卡配置错误。

修复措施：

- 所有构建经 build_exe_onnx.ps1 执行，保留 Poppler PATH 过滤。
- 增加 DistPath 参数，旧目录占用时可以直接构建到新目录。
- 增加 onnx_tools/verify_packaged_icu.py，对 Qt 所需 ICU 导出符号逐项校验。
- 旧错误包在校验中被拒绝；修正版使用本机 Windows 提供的兼容 ICU。
- 新版本应完整解压到空目录，不能覆盖带有旧 ICU DLL 的目录。

## 验证与发布

- 项目 Python 3.12 64 位环境：17 项单元测试通过。
- ICU 修正版：符号校验通过，实际启动确认助手主窗口创建，正常关闭返回 0。
- 正式包沿用同一应用源码重新构建，发布前再次检查 ICU 和启动行为。
- 自动化测试不覆盖所有游戏场景；本机启动成功不代表所有 Windows 版本都验证通过。
- 发布 ZIP 与 SHA-256 校验文件，不携带个人配置和会话日志。
